## Why `jz_exp` needed a special strategy

`jz_exp` and `upstream/main` are parallel branches. This fork renamed the
package `sisyphus` → `openbioacademia` and rewrote nearly every file, while
upstream added a new tool layer under the old `sisyphus` name. A normal
3-way merge cannot cleanly keep all local changes, because it produced a
broken hybrid: conflict regions kept the local side, but non-conflicting
upstream edits still landed, so files like `tools/citation_verifier.py`
came out as a 650-line mix using upstream's `net`/`settings`/`ThreadPoolExecutor`
imports instead of this fork's 304-line `urllib.request` version.

A dry-run merge was aborted before any commit. The chosen strategy
`git merge -s ours upstream/main` records `upstream/main` as an ancestor of
`jz_exp` (so git considers the branch up to date) while leaving the
working tree untouched.
