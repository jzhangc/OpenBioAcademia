## Starting state

The working tree already carried **uncommitted V2 work from a prior session**
(`tools/agents.py --format v2` transform, `OC_FORMAT` in `install.sh`, README
section, 3 tests, a draft `docs/opencode-v1-v2.md`). HEAD had no V2 support at
all. That WIP was assessed against the official OpenCode V1→V2 migration guide
and the V2 config/agents/permissions references, then completed and corrected.

Issues found before this session's changes:

1. `config/agent-config.json` shipped hardcoded `/Users/jingzhang/…` paths;
   `install.sh`'s sed only rewrites `/root/…` placeholders, so other machines
   inherited another user's absolute paths.
2. `install.sh configure_models` sed-matched `"9router/opencode-free"`, a model
   that no longer exists in the config; provider answers silently did nothing,
   and rendering ran *before* the config update anyway.
3. The v2 render kept the V1-only per-agent `skills:` field (10 agents), which
   V2 ignores, falsifying the "warning-free" claim.
4. No warning for `OC_FORMAT=v2` combined with a detected V1 binary (the v2
   format does not load on V1, agents would fall back to default permissions).
5. `docs/opencode-v1-v2.md` stated "earlier rules win" (inverted V2 semantics)
   and its "after" example did not match actual renderer output.
6. README `opencode.json` examples used V2-only key names (`commands`, `skills`
   array) without version annotation; silently ignored on V1.
7. CONTRIBUTING.md's agent template used flow-style maps the v2 transform
   mis-parses, plus a hardcoded path.
8. Docs stale: `docs/guide/installation.md` (the file the README hands to
   install agents) was fully pre-rename; `AGENTS.md` onboarding did not reflect
   the real `tools/` or the v1/v2 conventions.

## What changed

**`tools/agents.py`** (dual-format renderer)

- Kept and completed the WIP `_transform_permissions`: V1 `permission:` block →
  V2 `permissions:` ordered array; renames `bash`→`shell`, `task`→`subagent`,
  `write`/`patch`→`edit`; OMO-only actions (`call_omo_agent`, `doom_loop`,
  `plan_enter/exit`, `repo_clone/overview`) emitted as comments; rule order
  preserved (load-bearing: V2 is last-matching-rule-wins).
- Added `_strip_v1_skills`: v2 output drops the V1-only `skills:` block (block
  and inline list forms; names kept in the comment).
- Flow-style maps in a `permission:` block now raise `ValueError` with an
  actionable message instead of emitting a broken rule (reviewer finding S1).
- Effects are unquoted before re-quoting (fixes double-quoting of quoted
  effects).
- Fixed 4 pre-existing `E741` violations left by the WIP.

**`install.sh`**

- OpenCode major-version detection with guards: warns `OC_FORMAT=v2` + V1
  binary; hints v1→v2 on V2 installs; fail-safe under `set -euo pipefail` when
  the `opencode` binary is absent.
- New `provider_model()` maps the interview's provider choice to a concrete
  model and passes it as `--default-model` at render time, so rendered agents
  actually receive the chosen provider (previously a silent no-op).
- `configure_models` rewritten as a JSON round-trip that replaces only agents
  using the repo's current `default_model` (per-agent customizations survive),
  replacing the dead `9router/opencode-free` sed.

**`config/agent-config.json`**

- Hardcoded developer paths → `/root/openbioacademia` and
  `/root/.config/opencode` placeholders that `install.sh` rewrites at install
  time (26 lines, pure substitution; verified no real user paths remain).

**`tests/test_agents.py`**: 11 v1/v2 tests (3 from WIP + 8 new). Covers action
mapping, skills stripping (block/inline/empty), v1 byte-identity, all-25-agent
v2 invariants, full rule-order pin for `writer.md`, flow-style fail-loud,
quoted-effect unquoting, no-permission-block render, source `model:`
replacement, `main(["--format","v2",…])` CLI wiring, `install(fmt="v2")`
end-to-end, YAML validity of all 25 v2 frontmatters (skips if PyYAML absent).

**Docs**
